# ULTRON Memory Layers — Architecture & Policies

*Version: S3 (v13.6.0 "LAYERED MEMORY") · Last updated: 2026-05-05*

---

## Overview

ULTRON uses a three-layer memory system that balances token efficiency with
context relevance. Each layer has a distinct generation trigger, token budget,
and access pattern.

```
┌─────────────────────────────────────────────────────────────────────┐
│                     ULTRON MEMORY HIERARCHY                          │
├───────────┬──────────────────────────────────────────────────────────┤
│ Layer     │ Description                                              │
├───────────┼──────────────────────────────────────────────────────────┤
│ L0        │ Pinned context · always injected · regenerated/session   │
│           │ File: ~/.ultron/.tmp/L0-pinned.md                        │
│           │ Budget: ~200 tokens                                      │
│           │ Content: user identity, current focus, BLOCKING alerts,  │
│           │          session mode                                     │
├───────────┼──────────────────────────────────────────────────────────┤
│ L1        │ Warm context · queried per-prompt · on-demand            │
│           │ Files: ~/.ultron/memory/L1/*.md                          │
│           │ Budget: ~600 tokens per packet                           │
│           │ Content: projects-active, recent-decisions, skills-      │
│           │          routing, system-state                           │
├───────────┼──────────────────────────────────────────────────────────┤
│ L2        │ Cold vault · on-demand only · gated access               │
│           │ Source: ~/.ultron-vault/ (538+ notes + brain_index.db)   │
│           │ Budget: up to 700 tokens per packet                      │
│           │ Access gate: /deep prefix OR dispatcher conf ≥ 0.90      │
└───────────┴──────────────────────────────────────────────────────────┘
```

---

## Token Budget

| Layer | Per-packet cap | Trigger |
|---|---|---|
| L0 | 200 tok | Every session start |
| L1 | 600 tok | Dispatcher conf ≥ 0.70 |
| L2 | 700 tok | `/deep` prefix OR conf ≥ 0.90 |
| **Total session** | **~1500 tok** | (L0 + up to 2×L1 + optional L2) |

Token estimation: `len(content) // 4` (GPT-style, same as brain_index.py).
Enforcement: `token_budget.enforce(content, limit, priority_prefix)`.

## Generation Flow

### Session Start (SessionStart hook)

```
session-init.ps1
├── 1. Read stdin session_id
├── 2. Drain pending vault push-queue (push-queue job, 5s timeout)
├── 3. Prime decay cache + pending actions (parallel jobs)
├── 4. Generate current-session.json
├── 5. Run context_primer.py (context.md ≤ 400 tok, 8s timeout)
├── 6. Inject unacked alerts into context.md (alerts.py, 4s timeout)
├── 7. [S3-A NEW] Generate L0-pinned.md (generate_L0.py, Hidden background)
└── 8. [S2-A] Brain index staleness check (update if >4h, Hidden background)
```

### Per-Prompt (UserPromptSubmit hook)

```
intent-dispatcher.py
├── Budget: 40ms hard cap (shared across all steps)
├── Step 1: Slash-command short-circuit (skip /commands)
├── Step 2: Rules exact-match (intent-rules.yaml, pre-compiled regex)
├── Step 3: ZTMSI query (chunks_fts BM25, direct sqlite3 read-only)
├── Step 4: [S3-B NEW] Context packet build (if conf ≥ 0.70, ≥10ms left)
│           └── context_packet_builder.build(prompt, "L1", 600)
│               └── [CTX·L1·{domain}·{tokens}tok] {content}
└── Stdout: routing line + optional CTX line (2 lines max)
```

### Session End (Stop hook)

```
stop-memory-sync.ps1
├── Phase A (always, parallel): brain_index.update + decay_queue.prime +
│   memory_bridge.ingest + route_quality_aggregator + consistency_check
├── context_primer.py (regenerate context.md for next session)
├── Phase B (HIGH/ULTRA/LEARN only): vault sync + push-async + compactor
├── session_highlights.py (extract + prime recent-highlights.json)
└── [S3-B NEW] Token usage session-end marker → token-usage.jsonl
```

## Layer Details

### L0 — Pinned Context

Generated by `generate_L0.py` at every session start (background, Hidden
process). Output is a static markdown file read by Claude at turn 0.

**Content structure:**
```
# ULTRON L0 [2026-05-05T19:00Z]
👤 USER · Ing. Programación + PROGRAM_A · Stack: C++/UE5/C#/Unity/TS/Python
🎯 Foco: ULTRON v14 Genesis — S3 implementation
🚨 BLOCKING: ninguno
⚡ Modo: MEDIUM
```

**Priority enforcement:** `[BLOCKING]` lines are always preserved when
truncation occurs. Non-blocking content is trimmed from the bottom.

**Focus source:** `~/.ultron/memory/focus.json` — set via
`ultron focus set "Project X — task Y"`.

**Alerts source:** `~/.ultron/alerts.jsonl` — unacked entries with
`severity=blocking`.

### L1 — Warm Context

Four markdown files indexed by `brain_index.py` in the `chunks_fts` table:

| File | Layer tag | Key content |
|---|---|---|
| `projects-active.md` | L1-projects | Genesis status, BildyApp, Nexus |
| `recent-decisions.md` | L1-decisions | ADRs, architecture choices |
| `skills-routing.md` | L1-skills | Skill triggers, Dual Mode guide |
| `system-state.md` | L1-system | Version, hooks, MCP, health |

Queried via `context_packet_builder.build(query, "L1", 600)` which runs a
direct FTS5 BM25 query against `chunks_fts` filtered by `layer LIKE 'L1-%'`.

### L2 — Cold Vault

The full `~/.ultron-vault/` corpus (538+ notes) indexed in `brain_index.db`.
Access is rate-gated to avoid context bloat:
- Explicit: user types `/deep` prefix
- Automatic: dispatcher confidence ≥ 0.90 (very high certainty match)

## Token Usage Log

Written to `~/.ultron/.tmp/token-usage.jsonl` by `token_budget.log()`.
Each line is a JSONL event:
```json
{"ts": "2026-05-05T19:00:00Z", "layer": "L0", "tokens": 145, "limit": 200}
{"ts": "2026-05-05T19:01:23Z", "layer": "L1", "tokens": 420, "limit": 600}
```
Session-end summary (from `stop-memory-sync.ps1`):
```json
{"ts": "2026-05-05T21:45:00Z", "event": "session_end", "date": "2026-05-05"}
```

Full `L0=N L1=M L2=P total=T/1500tok` aggregation planned for v13.7.0 (S4).
