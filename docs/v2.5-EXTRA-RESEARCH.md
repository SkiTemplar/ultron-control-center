## 1. Graphify (safishamsi/graphify) — 52,409 stars

**What it is:** AI coding assistant skill that turns ANY folder (code, SQL, R scripts, docs, papers, images, videos) into a queryable knowledge graph. Multi-CLI: Claude Code, Codex, OpenCode, Cursor, Gemini.

**Why this matters for USER:**
- Replaces what ULTRON `brain_index.py` + Qdrant did, but as a **skill not a backend** — zero infra.
- Indexes graphics/UE5/AI projects so Claude can answer "where does shader X get called?" without re-reading the tree every session.
- Could feed the ECC memory graph automatically as a one-shot per project.

**Integration plan:**
1. Add to `cockpit/curated-catalog.json` under new domain `knowledge-graphs`.
2. Install in a specific project (e.g. PROGRAM_B) as a per-project skill.
3. Wire a "Build knowledge graph" button in `ProjectContext.tsx` that runs Graphify against the project root.
4. Surface the graph in the Library Catalog tab once initial query interfaces stabilise.

**Estimated effort:** 1-2 h initial wiring + per-project indexing.

## 3. ULTRON memory verdict: STAY ARCHIVED

**Honest analysis based on what was in the codebase:**

What ULTRON memory did:
- `brain_index/` — Qdrant vector DB with embeddings of skills, agents, prompts, past sessions. Used for RAG over the user's own content.
- `vault/` (skill-vault) — versioned snapshots of skills with security findings.
- `intent-rules.yaml` — natural-language -> skill routing (e.g. "compila el shader" -> activate `shader-fundamentals` skill).
- `personal/known.json` — auto-extracted user facts (style, recent topics, routines).

What replaced it:
- **Mem0 cloud** — persistent cross-session memory with semantic search. Replaces `personal/known.json` + session memory cleanly.
- **ECC memory MCP** (`mcp__plugin_ecc_memory__*`) — local knowledge graph (entities + relations + observations). Replaces the brain_index RAG for entity-style recall.
- **ECC natural-language skill activation** — every ECC skill has a description that Claude reads. Asking "compila el shader" naturally triggers the right skill without a YAML router.
- **Skill descriptions in CC Library Commands tab** (v2.5) — visual discovery instead of programmatic routing.

What's still missing vs ULTRON:
- **RAG over user's own files** (the brain_index Qdrant did this). Graphify covers it FAR better as a per-project skill.
- **Security findings on skills** (vault scan). Trail of Bits skills (in v2.3 catalog) can replace.

**Recommendation:** keep ULTRON memory archived as cold storage. Graphify + Mem0 + ECC memory cover the same ground with 1/10 the complexity. If a brain_index-style global search is ever needed again, install Graphify as a global skill instead of resurrecting `brain_index.py`.

## 6. Free-tier LLM APIs for background tasks

User asked about using free APIs to delegate low-value work (memory consolidation, prompt rewriting, etc).

**Where this fits in CC:**

- Cost: 2-3 h. Worth doing once everything else is stable.

**Defer to v2.7+** (lower urgency than UI gaps).

## 7. Vector DB / RAG revisit

User mentioned they liked the vector DB approach.

**Options:**
- **Graphify** (above) — already a skill, indexes folders. No infra.
- **sqlite-vec** — vector index inside SQLite. Lightest possible. ~50 LOC to wire.
- **LanceDB** — Rust-native, columnar. Good for >1M vectors. Overkill for personal use.
- **ChromaDB** — heaviest. Skip.

**Recommendation:** **Graphify first** (covers 90%). If still missing semantic search inside ProjectNotes, add `sqlite-vec` as a tiny embedded index. **Do NOT bring back Qdrant.**
