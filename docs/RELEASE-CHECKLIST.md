# Release Checklist

Pre-flight checklist for every public release of ULTRON Control Center.
Run every item before following `docs/RELEASE-PROCESS.md` to cut the tag.

> See `docs/RELEASE-PROCESS.md` §1 for the full per-release flow, and
> `docs/CHANGELOG-POLICY.md` for the versioning policy (patch / minor / major).

---

## 1. Source tree

- [ ] Working tree is clean: `git status` shows no uncommitted changes.
- [ ] On `main` (or the designated release branch) and up to date with origin.
- [ ] No stale merge conflicts (`git diff --check` exits 0).

## 2. Automated checks — all must be green

- [ ] `cargo test` passes (all tests, including `--features finance qdrant`).
- [ ] `cargo clippy -- -D warnings` exits 0.
- [ ] `cargo fmt --check` exits 0 (no formatting drift).
- [ ] TypeScript check: `cd control-center && npx tsc --noEmit` exits 0.
- [ ] Version drift guard: `uv run python scripts/cockpit/version_propagate.py --check`
      exits 0 (the three Control Center manifests agree — `package.json`,
      `Cargo.toml`, `tauri.conf.json`).

## 3. Personal-data gate

- [ ] PII leak scan: `uv run python scripts/cockpit/audit_personal_data.py` reports
      HIGH = 0 before any tag push. This is a CI gate; do not skip.

## 4. App build (local)

- [ ] Close the running ULTRON instance (the binary is locked while the app is open).
- [ ] Build from `control-center/` with `npm run build:local` (Finance + qdrant features).
- [ ] Binary exits 0, no Rust warnings in the output.
- [ ] Memory sidecar health: `bin/ultron-memory.exe doctor` passes all checks.

## 5. Runtime smoke tests

- [ ] Launch the freshly built binary. App opens without crash or console errors.
- [ ] Settings → About shows the expected version number.
- [ ] AI Router panel is reachable and at least one zone shows a valid primary.
- [ ] Memory → Recall returns results for a known query (e.g. "qdrant embeddings").
- [ ] Kanban board loads without JS exceptions.

## 6. Version numbers

Verify that these three files carry the **same** Control Center version (`2.x`):

- [ ] `control-center/package.json` → `"version"`
- [ ] `control-center/src-tauri/Cargo.toml` → `version`
- [ ] `control-center/src-tauri/tauri.conf.json` → `"version"`

For minor/major bumps, use `./scripts/cut-release.ps1 -NewVersion vX.Y.0 -DryRun`
to preview before writing.

## 7. CHANGELOG (minor and major only)

- [ ] For a **patch** bump: nothing to do — `scripts/hooks/auto-changelog.py`
      buffers it automatically.
- [ ] For a **minor or major** bump: confirm that `CHANGELOG.md` has a section for
      this version (either hand-written or auto-generated by the hook), formatted
      per `docs/CHANGELOG-POLICY.md`.
- [ ] Mirror entry exists in `cockpit/changelog.ndjson` (the hook writes both;
      verify if the section was added by hand).

## 8. GitHub Actions prerequisites

- [ ] `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` are
      present in repo Secrets (one-time setup; see `docs/RELEASE-PROCESS.md` §0).
- [ ] `release.yml` (currently `release.yml.disabled`) is enabled or the release
      assets will be built and attached by `scripts/cut-release.ps1`.

## 9. Tag and push

After every box above is ticked:

```powershell
# Preferred: let the helper script bump, tag, and push atomically.
.\scripts\cut-release.ps1 -NewVersion vX.Y.Z

# Manual alternative (see docs/RELEASE-PROCESS.md §1.4 for full git commands).
```

Then watch the Actions tab until the release workflow goes green and the
GitHub Releases page has the expected assets (`setup.exe`, `latest.json`, etc.).

## 10. Post-release verification

- [ ] GitHub Release page exists with the correct tag and assets.
- [ ] `latest.json` is attached and readable (download + `Get-Content`).
- [ ] Install on a clean Windows 11 machine; confirm the version shown in About.
- [ ] (Optional, if upgrading from a previous install) Auto-updater prompts and
      completes successfully.

---

> **Rollback**: if a regression ships, mark the release as a pre-release in the
> GitHub UI (removes it from `/releases/latest`, pointing the auto-updater at the
> previous good version), then cut a patch. See `docs/RELEASE-PROCESS.md` §Rollback.
