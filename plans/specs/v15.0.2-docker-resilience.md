# v15.0.2 — Docker / Qdrant Resilience + Retry UX

> Patch. Cierra el bucle silencioso de `ensure-qdrant.ps1`: cuando D:\ no está montado o Docker falla en arranque, el usuario nunca se entera hasta que intenta usar recall.
> Status: in-progress · Owner: USER · Created 2026-05-13

## Problem

`ensure-qdrant.ps1` (hook `SessionStart` background) ya detecta correctamente:
- `disk-missing` (D:\ no montado, Docker apuntaba ahí su WSL distro)
- `container-missing`
- `daemon-down` / `unhealthy` / `unreachable`

Pero el resultado solo se escribe a `~/.ultron/.tmp/qdrant-health.json` y nadie lo surfacea. El síntoma observado por USER: arrancar el PC sin D:\ conectado, abrir Claude, Qdrant en silencio offline, fallos posteriores en recall.

## Non-goals

- NO auto-retry event-driven (volume watcher WMI). Si el primer arranque falla, el retry es **manual** vía botón en toast.
- NO abrir Docker Desktop UI cuando falla. Comportamiento explícitamente rechazado.
- NO notificación cuando todo va bien (`status=up`). Silencioso por diseño.

## Constraints

- Windows 11, PowerShell 5.1. (PS7 no garantizado en `SessionStart`.)
- Hook background, no debe bloquear `SessionStart`.
- Diseño "cómodo, no invasivo": máximo 1 toast por sesión por exit-code distinto.

## Design

### Componentes

```
ensure-qdrant.ps1               (existe)   escribe qdrant-health.json
qdrant-notify.ps1               (nuevo)    lee health.json + WinForm persistente
qdrant-toast-state.json         (nuevo)    anti-spam: último status notificado
install-qdrant-bootcheck.ps1    (nuevo)    registra task ULTRON-QdrantBoot
session-init.ps1                (mod)      solo refresca health.json (sin panel)
Scheduled Task ULTRON-QdrantBoot (nueva)   LogonTrigger del user → corre chain
```

### Trigger: scheduled task, no SessionStart de Claude

Razón: el usuario quiere ver la pantallita **al arrancar el ordenador**, no al abrir Claude. Una scheduled task con LogonTrigger se dispara en cuanto el escritorio está listo (~10-15s tras login). El panel sale antes de que Claude esté abierto.

`session-init.ps1` mantiene su llamada a `ensure-qdrant.ps1` para refrescar `qdrant-health.json` (lo lee `context_primer`) pero NO dispara panel — el panel es responsabilidad exclusiva de la scheduled task, evitando que cada sesión Claude muestre una ventana.

### Por qué WinForm y no toast nativo

BurntToast respeta la configuración de notificaciones de Windows. Si el usuario tiene Focus Assist activo o notificaciones desactivadas, el toast desaparece sin avisar (caso real de USER). Una WinForm `TopMost` es una ventana normal: siempre se ve, independiente de notification center.

### Persistente

El panel **no auto-cierra**. Se queda hasta que el usuario haga click en Reintentar, Silenciar o la X. Razón: si te avisa de que falta D:\ y vas a por el USB, no quieres que desaparezca en 60s antes de volver.

### Encoding

Strings 100% ASCII (sin `·`, sin tildes) + archivo guardado con BOM UTF-8. Defensa en profundidad contra cp1252 default de PS5.1.

### Flujo

1. `SessionStart` → `session-init.ps1` lanza `ensure-qdrant.ps1` background (ya existe).
2. `ensure-qdrant.ps1` corre, escribe `qdrant-health.json`, sale con exit-code.
3. `session-init.ps1` lanza `qdrant-notify.ps1` background **después** (delay 2s para que health.json esté escrito).
4. `qdrant-notify.ps1`:
   - Lee `qdrant-health.json`.
   - Si `status=up` → nada.
   - Si `status` ya notificado en `qdrant-toast-state.json` esta sesión → nada.
   - Si nuevo problema → dispara toast accionable (BurntToast).
   - Persiste el status notificado.

### Panel por status

| Status | Título | Body | Botones |
|---|---|---|---|
| `disk-missing` | ULTRON \| Qdrant offline | "Drive D:\ no detectado. Conecta el USB o monta el disco y pulsa Reintentar." | [Reintentar] [Silenciar] |
| `container-missing` | ULTRON \| Qdrant setup | "Contenedor ultron-qdrant no existe. Abre una terminal y ejecuta 'ultron qdrant setup', o copia el comando con el boton." | [Copiar setup] [Silenciar] |
| `daemon-down` | ULTRON \| Docker no responde | "Docker daemon no arranco. Comprueba Docker Desktop y pulsa Reintentar." | [Reintentar] [Silenciar] |
| `unhealthy` / `unreachable` | ULTRON \| Qdrant degradado/inalcanzable | "Container up pero healthz {ko}." | [Reintentar] [Silenciar] |
| `up` (success-on-retry) | ULTRON \| Qdrant up | "Recall semantico de vuelta. Todo OK." | [OK] |

**Reintentar:** lanza en background `ensure-qdrant.ps1` + chain a `qdrant-notify.ps1 -SuccessOnRetry`. Si OK → panel verde "Qdrant up" (auto-cierra en 6s). Si falla otra vez → panel original.

**Silenciar:** cierra el panel sin reintentar. El state file ya está persistido, así que no vuelve a aparecer hasta próxima sesión o cambio de status.

### Stack

- **WinForms** (`System.Windows.Forms`) directo desde PowerShell. Sin módulos externos. Funciona en PS5.1 default.
- Posición: bottom-right de la pantalla primaria con margen 20px.
- Tamaño: 480×200 px, `FormBorderStyle = None`, `TopMost = $true`, `ShowInTaskbar = $false`.
- **Persistente**: sin timer de auto-close.
- Tema: fondo oscuro `#161820`, frame 1px gris `#3C4050`, strip superior de 4px (rojo `#E85959` fallos, verde `#38B26E` success), título Segoe UI Semibold 12pt, body Segoe UI 10pt.
- Botones: 110×32, FlatStyle, accent azul `#586EFF` para acciones primarias, gris oscuro `#262A36` para secundarias.
- Close-X manual top-right.
- Fallback: si `Add-Type` falla (caso extremo), escribe a `~/.ultron/alerts.jsonl` y exit 0.

### Scheduled task

`ULTRON-QdrantBoot` registrada por `install-qdrant-bootcheck.ps1`:
- Trigger: `-AtLogOn -User $env:USERNAME`
- Principal: Interactive logon, `RunLevel Limited` (sin admin)
- Settings: StartWhenAvailable, AllowStartIfOnBatteries, ExecutionTimeLimit 5min, MultipleInstances IgnoreNew, Hidden
- Action: `powershell.exe -NoProfile -Sta -ExecutionPolicy Bypass -Command "Start-Sleep -Seconds 12; & ensure-qdrant; Start-Sleep -Seconds 1; & qdrant-notify"`
- Delay 12s: deja que Docker Desktop arranque tras autostart antes de probar el daemon.

Comandos del instalador:
```
.\install-qdrant-bootcheck.ps1 install     # registrar
.\install-qdrant-bootcheck.ps1 uninstall   # borrar
.\install-qdrant-bootcheck.ps1 status      # ver estado
.\install-qdrant-bootcheck.ps1 run-now     # disparar ahora
```

## Fail-fast order

1. `qdrant-health.json` no existe → notify sale 0 (silencioso). ensure-qdrant aún corriendo.
2. WinForms no carga (caso teórico) → alerts.jsonl + exit 0.
3. `status=up` → exit 0.
4. status ya notificado esta sesión → exit 0 (anti-spam).
5. status nuevo → persist state → mostrar WinForm → si "Reintentar" lanza chain.

## Success Criteria

- [ ] Encender el PC → ~15s después del logon, panel visible (sin abrir Claude).
- [ ] Panel se queda visible hasta que el usuario actúe (no auto-close).
- [ ] Strings en español sin caracteres rotos (`·`, tildes) gracias a ASCII + BOM UTF-8.
- [ ] Click "Reintentar" tras corregir el problema → panel verde "Qdrant up".
- [ ] Click "Silenciar" / X → desaparece y no vuelve esa sesión.
- [ ] Click "Copiar setup" en container-missing → comando en portapapeles.
- [ ] Estado `up` → ningún panel.
- [ ] Funciona con notifications de Windows desactivadas.
- [ ] WinForms falla teóricamente → alerts.jsonl + exit 0.

## Rollback

```powershell
& ~/.ultron/scripts/hooks/install-qdrant-bootcheck.ps1 uninstall
```

Borra la scheduled task. Los scripts quedan en disco pero no se disparan. `session-init.ps1` sigue refrescando `qdrant-health.json` (no panel). Reversión completa.
