# v15.0.2 — Docker / Qdrant Resilience + Retry UX

> Patch. Cierra el bucle silencioso de `ensure-qdrant.ps1`: cuando D:\ no está montado o Docker falla en arranque, el usuario nunca se entera hasta que intenta usar recall.
> Status: in-progress · Owner: USER · Created 2026-05-13

## Problem

`ensure-qdrant.ps1` (hook `SessionStart` background) ya detecta correctamente:
- `disk-missing` (D:\ no montado, Docker apuntaba ahí su WSL distro)
- `container-missing`
- `daemon-down` / `unhealthy` / `unreachable`

Pero el resultado solo se escribe a `~/.ultron/.tmp/qdrant-health.json` y nadie lo surfacea. El síntoma observado por USER: arrancar el PC sin D:\ conectado, abrir Claude, Qdrant en silencio offline, fallos posteriores en recall.

## Non-goals

- NO auto-retry event-driven (volume watcher WMI). Si el primer arranque falla, el retry es **manual** vía botón en toast.
- NO abrir Docker Desktop UI cuando falla. Comportamiento explícitamente rechazado.
- NO notificación cuando todo va bien (`status=up`). Silencioso por diseño.

## Constraints

- Windows 11, PowerShell 5.1. (PS7 no garantizado en `SessionStart`.)
- Hook background, no debe bloquear `SessionStart`.
- Diseño "cómodo, no invasivo": máximo 1 toast por sesión por exit-code distinto.

## Design

### Componentes

```
ensure-qdrant.ps1          (existe)      escribe qdrant-health.json
qdrant-notify.ps1          (nuevo)       lee health.json + abre WinForm flotante
qdrant-toast-state.json    (nuevo)       anti-spam: último status notificado
session-init.ps1           (mod)         chainea ensure → sleep 1s → notify
```

### Por qué WinForm y no toast nativo

BurntToast respeta la configuración de notificaciones de Windows. Si el usuario tiene Focus Assist activo o notificaciones desactivadas globalmente, el toast desaparece sin avisar — eso es exactamente lo que pasó en la prueba real. Una WinForm `TopMost` es una ventana normal: siempre se ve, independiente de la config de notification center. Trade-off: no se queda en notification center si la ignoras (auto-cierre 60s y se va).

### Flujo

1. `SessionStart` → `session-init.ps1` lanza `ensure-qdrant.ps1` background (ya existe).
2. `ensure-qdrant.ps1` corre, escribe `qdrant-health.json`, sale con exit-code.
3. `session-init.ps1` lanza `qdrant-notify.ps1` background **después** (delay 2s para que health.json esté escrito).
4. `qdrant-notify.ps1`:
   - Lee `qdrant-health.json`.
   - Si `status=up` → nada.
   - Si `status` ya notificado en `qdrant-toast-state.json` esta sesión → nada.
   - Si nuevo problema → dispara toast accionable (BurntToast).
   - Persiste el status notificado.

### Panel por status

| Status | Título | Body | Botones |
|---|---|---|---|
| `disk-missing` | ULTRON · Qdrant offline | "Drive D:\ no detectado. Conecta el USB o monta el disco y reintenta." | [Reintentar] [Silenciar] |
| `container-missing` | ULTRON · Qdrant setup | "Contenedor `ultron-qdrant` no existe. Ejecuta `ultron qdrant setup` en una terminal." | [Silenciar] |
| `daemon-down` | ULTRON · Docker no responde | "Docker daemon no arrancó. Comprueba Docker Desktop y reintenta." | [Reintentar] [Silenciar] |
| `unhealthy` / `unreachable` | ULTRON · Qdrant degradado/inalcanzable | "Container up pero healthz {ko}." | [Reintentar] [Silenciar] |
| `up` (success-on-retry) | ULTRON · Qdrant up | "Recall semántico de vuelta. Todo OK." | [OK] |

**Reintentar:** lanza en background `ensure-qdrant.ps1` + chain a `qdrant-notify.ps1 -SuccessOnRetry`. Si OK → panel verde "Qdrant up" (auto-cierra en 6s). Si falla otra vez → panel original.

**Silenciar:** cierra el panel sin reintentar. El state file ya está persistido, así que no vuelve a aparecer hasta próxima sesión o cambio de status.

### Stack

- **WinForms** (`System.Windows.Forms`) directo desde PowerShell. Sin módulos externos. Funciona en PS5.1 default.
- Posición: bottom-right de la pantalla primaria con margen 24px.
- Tamaño: 420×170 px, `FormBorderStyle = None`, `TopMost = $true`, `ShowInTaskbar = $false`.
- Auto-close: 60s para fallos, 6s para success.
- Tema: fondo oscuro (`#161820`), strip de color superior (rojo `#E85959` para fallos, verde `#38B26E` para success), título Segoe UI Semibold, body Segoe UI 9pt, botón principal accent ULTRON.
- Fallback: si `Add-Type System.Windows.Forms` falla (caso extremo), `qdrant-notify.ps1` escribe a `~/.ultron/alerts.jsonl` y termina silenciosamente.

### Diseño "cómodo, no invasivo"

- Pequeño y en esquina, no en el centro.
- TopMost para garantizar visibilidad incluso jugando, pero sin sonido y sin robar foco.
- Sin entry en taskbar — desaparece sin trazas si se auto-cierra.
- Close-X manual (×) en esquina si lo quieres cerrar antes del timer.

## Fail-fast order

1. `qdrant-health.json` no existe → notify sale 0 (silencioso). ensure-qdrant aún corriendo.
2. WinForms no carga (caso teórico) → alerts.jsonl + exit 0.
3. `status=up` → exit 0.
4. status ya notificado esta sesión → exit 0 (anti-spam).
5. status nuevo → persist state → mostrar WinForm → si "Reintentar" lanza chain.

## Success Criteria

- [ ] Arrancar PC sin D:\ → abrir Claude → toast accionable visible <10s después de SessionStart.
- [ ] Click "Reintentar" tras conectar D:\ → Qdrant arranca, toast "Qdrant up" aparece.
- [ ] Click "Silenciar" → no vuelve a aparecer toast en esa sesión.
- [ ] Estado `up` desde inicio → ningún toast (no spam silencioso).
- [ ] WinForms no carga (teórico) → alerts.jsonl tiene entrada, ningún error en stderr, SessionStart no bloquea.
- [ ] Funciona con notification settings de Windows desactivadas (que es el caso real de USER).

## Rollback

`qdrant-notify.ps1` es opt-in. Para desactivar: borrar la línea que lo invoca en `session-init.ps1` (o renombrar el script). `ensure-qdrant.ps1` queda intacto.
