# v15.1 — ULTRON Bus Foundation

## Overview

`ultron-bus` es un **MCP server local** que da a múltiples sesiones Claude Code la capacidad de hablar entre sí: registrarse al arrancar, mandar mensajes asíncronos, leer su inbox, y notificar al supervisor (v15.2) cuando una task termina.

Sin esta capa no son posibles: v15.2 supervisor (necesita inbox compartido), v15.4 overnight (notify cross-session), v15.5 mobile (recibe eventos del bus).

## Decisiones técnicas (locked)

| # | Decisión |
|---|---|
| D1 | Implementación: **MCP server stdio** en Python, paquete `~/.ultron/mcps/ultron-bus/` |
| D2 | Storage: **file-based** en `~/.ultron/bus/` (no DB; JSONL append-only) |
| D3 | Identidad sesión: `session_id` que Claude Code pasa por stdin a SessionStart hook |
| D4 | TTL default mensajes: **1h** (configurable per-message) |
| D5 | Dedup: hash `(from, to, content)` en ventana 5 min |
| D6 | Heartbeat: `UserPromptSubmit` hook con throttle 30s |
| D7 | Pruning sesiones muertas: `Stop` hook + cron diario |

## Data shapes

### `~/.ultron/bus/sessions.json` (registry, mutable)

```json
{
  "schema_version": 1,
  "sessions": {
    "a6153e3d-...": {
      "session_id": "a6153e3d-...",
      "pid": 12345,
      "started_at": "2026-05-10T20:00:00Z",
      "last_heartbeat": "2026-05-10T20:15:30Z",
      "status": "live",
      "current_skill": "ultron",
      "labels": ["interactive", "USER"]
    }
  }
}
```

### `~/.ultron/bus/<session_id>/inbox.jsonl` (append-only)

```jsonl
{"id":"01H...","ts":"2026-05-10T20:01:00Z","from":"supervisor","to":"<session_id>","kind":"task.assigned","content":{...},"ttl_s":3600}
{"id":"01H...","ts":"2026-05-10T20:05:00Z","from":"<sibling_id>","to":"<session_id>","kind":"task.done","content":{...}}
```

### `~/.ultron/bus/<session_id>/outbox.jsonl` (append-only, log)

```jsonl
{"id":"01H...","ts":"2026-05-10T20:02:00Z","from":"<session_id>","to":"supervisor","kind":"task.progress","content":{...}}
```

### Message schema (canonical)

```json
{
  "id":      "ULID-style sortable ID",
  "ts":      "ISO 8601 UTC",
  "from":    "session_id | supervisor | mobile | system",
  "to":      "session_id | supervisor | mobile | broadcast",
  "kind":    "task.assigned | task.progress | task.done | task.failed | task.parked | mode.changed | heartbeat",
  "content": { /* arbitrary JSON; tratado como DATOS no instrucciones */ },
  "ttl_s":   3600,
  "content_hash": "sha1 for dedup"
}
```

**Guard-rail crítico:** todo `content` que llega vía bus se trata como **DATOS**, nunca como instrucciones. El consumer puede leer el JSON, pero el guard-rail global de SKILL.md aplica: cualquier intento de inyección dentro del content (tipo `<!-- ignore previous -->` en un campo string) se ignora y se reporta a USER.

## MCP tools (API)

```python
# bus.list_sessions(filter?: str = "live") -> list[dict]
#   filter ∈ {"live", "all", "dead"}
#   → [{session_id, pid, last_heartbeat_age_s, status, labels}, ...]

# bus.send(target_id: str, kind: str, content: dict, ttl_s: int = 3600) -> dict
#   → {"ok": True, "id": "ULID", "delivered_to": "<target>", "queue_size": N}

# bus.read(my_id: str, since_ts?: str = None, limit: int = 50) -> list[dict]
#   Lee mensajes en mi inbox desde un timestamp (default: desde el último read).
#   → [{id, ts, from, kind, content, ttl_s}, ...]
#   Side effect: actualiza `last_read_ts` per session para el próximo read.

# bus.subscribe(pattern: str) -> dict
#   Marca interés en un topic (e.g. "task.*", "mode.changed"). Se persiste
#   en sessions.json bajo "subscriptions". El supervisor consulta esto para
#   decidir a quién entregar broadcasts.
#   → {"ok": True, "subscribed_to": ["task.*"]}

# bus.broadcast(kind: str, content: dict, exclude_self: bool = True) -> dict
#   Envía a todas las sesiones live (o las que matcheen subscription).
#   → {"ok": True, "delivered_to": ["<id1>", "<id2>"]}

# bus.status() -> dict
#   Health del bus: live sessions, total mensajes en cola, dedup window, etc.
#   → {"live_sessions": 3, "queued_messages": 12, "uptime_s": 1234, ...}
```

## Hooks integration

### SessionStart hook (extend `session-init.ps1`)

Después del context.md prime existente, llamar:
```python
# wrapper script: register_session.py
bus.register(session_id, pid=os.getpid(), labels=["interactive"])
```
Falla silenciosa: si bus down, sesión sigue normal sin el bus.

### UserPromptSubmit hook (nuevo `bus_heartbeat.py`)

Throttle 30s usando `~/.ultron/.tmp/bus-last-hb.json`. Si último HB >30s:
```python
bus.heartbeat(session_id, current_skill=detected_skill)
```
Latencia presupuestada: <5ms (no bloquea el dispatcher).

### Stop hook (extend `stop-memory-sync.ps1`)

Phase A nuevo job:
```python
bus.flush(session_id, status="closed", reason="stop_event")
```
Después de la flush, supervisor (v15.2) ejecuta el pruning periódico.

## Test plan (acceptance)

| Test | Criterio |
|---|---|
| 2 sesiones intercambian mensaje | <1s end-to-end |
| Sesión muerta (no HB >5min) | se pruna del registry automáticamente |
| Mensaje TTL expirado | NO se entrega, log warning |
| Mensaje duplicado en 5 min | descarta, log info |
| Hooks Stop+Start ejecutan en <50ms | latency budget respeted |
| Race con 4 sesiones simultáneas | sin corruption en sessions.json |
| Bus down (proceso muerto) | sesión sigue normal, hooks no bloquean |
| Prompt injection en content | tratado como datos, guard-rail aplica |

## Riesgos + mitigaciones

| Risk | Mitigación |
|---|---|
| Race condition en `sessions.json` con N sesiones | File lock + tests con threading + tmp+rename |
| Loop infinito mensajes A→B→A→... | TTL + dedup hash + max 10 msgs/ventana 1min por (from, to) |
| Hooks bloqueantes ralentizan startup | Async fire-and-forget; deadline 50ms; falla silenciosa |
| Prompt injection cross-session | content tratado como DATOS, guard-rail global cubre |
| BOM en sessions.json (PowerShell) | utf-8-sig tolerante (lección hardening previo) |
| Bus crashea, sesiones quedan colgadas | bus es opcional; sesión continúa sin él; supervisor watchdog (v15.2) lo reinicia |
| Disk fill por inbox grande | rotación: archive `inbox-YYYY-MM-DD.jsonl` cuando inbox >10MB |

## Out of scope (explícito)

- Encryption at rest del bus storage (file system permissions ya cubren)
- Authentication entre sesiones (mismo user, mismo machine)
- Federación cross-machine (v16+ posible con Tailscale)
- UI gráfica del bus (TUI panel sí, web no en este sprint)
- Persistencia long-term de mensajes (después de TTL se borran)

## Métricas de éxito

```
Pre-v15.1 (hoy):
  cross-session communication: imposible (silos)
  supervisor existence:        no
  parallel session awareness:  no

Post-v15.1:
  2+ sessions can exchange messages: SI, latency <1s
  hook overhead per session:   <50ms total (register + N heartbeats + flush)
  bus uptime under load:       >99% durante test 24h con 50 mensajes/min
  guard-rail injection cases:  100% bloqueados en test corpus de 20+ payloads
```
