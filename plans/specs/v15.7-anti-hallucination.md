# v15.7 — Anti-Hallucination Layer

## Objetivo

Aplicar las técnicas SOTA 2025-2026 de detección y mitigación de
alucinaciones al sistema ULTRON, aprovechando su infraestructura ya
existente (`/dual` `/triple`, hooks pre/post-prompt, intent-dispatcher,
provenance ledger, constitution con safety_gates por persona).

## Filosofía rectora

**No aplicar siempre — enrutar dinámicamente por riesgo.** Las técnicas
anti-hallucination cuestan 3-10× más tokens. La estrategia ganadora del
estado del arte es: classify task → if high-risk → activate full layer;
if low-risk → generate directly.

## Componentes (5 fases)

### Phase 0 — Risk classifier (2-3 h)

**Qué:** Extender `intent-dispatcher.py` con un clasificador de riesgo
que devuelva `risk_level ∈ {low, medium, high}` además del skill.

**Reglas iniciales:**
- `high`: tareas con efectos secundarios (alfred, terry+commit, pana+email-send,
  warren+análisis, security-review)
- `medium`: investigación factual (einstein, novalbos, repo-evaluator)
- `low`: chat conversacional, narrativa (tolkien, manolo-lama, mike-tyson sin código)

**Output:** campo `risk_level` añadido a la línea routing
`[ULTRON·N%] skill=X | risk=high | ctx=...`.

**Tests:** `tests/test_risk_classifier.py` con 30+ pares prompt→risk.

---

### Phase 1 — Semantic Entropy Probe (3-4 h)

**Qué:** Hook post-prompt que para tareas `risk=high` pide al modelo `n=3`
respuestas con temperature alta y mide la varianza semántica.

**Implementación:**
1. Capturar prompt + primera respuesta
2. Re-llamar a Claude/Gemini con temp=0.9 dos veces más
3. Embedding de las 3 respuestas con MPNet (ya disponible)
4. Calcular varianza: 1 − media(cosine_sim entre pares)
5. Si varianza > 0.4 → activar `/triple` automáticamente o flag warning

**Costo:** +2 llamadas + 3 embeddings ≈ ~3× tokens. Solo en `risk=high`.

**Spec output:** registro en `~/.ultron/.tmp/entropy-probes.jsonl`
con `{prompt_hash, variance, action_taken}` para tunear thresholds.

---

### Phase 2 — Provenance Enforcement (2-3 h)

**Qué:** Forzar que cada entrada nueva en vault tenga `source_uri` +
`timestamp` + `extracted_by` (persona/hook).

**Implementación:**
1. Schema bump: `~/.ultron-vault/<X>.md` frontmatter requiere
   `source_uri: <chat-session|file-path|url>` y `extracted_by: <id>`.
2. `embed_vault.py` rechaza entries sin estos campos (con warning, no quarantine).
3. Reconciliation loop: cuando dos entries tienen mismo `topic` pero
   contradicción factual, crear alert en `alerts.jsonl` con severity=warn
   y mostrar en `ultron status` para revisión humana.
4. `ultron memory verify <topic>` — comando nuevo que muestra todas las
   entries con ese topic + sus provenances + diferencias.

**Backward-compat:** entries pre-spec reciben `source_uri="legacy"` y
`extracted_by="unknown"` (igual patrón que hicimos con `producer` en
pending_actions hardening).

---

### Phase 3 — Cross-Persona Janus Hook (3-4 h)

**Qué:** Hook post-prompt que para personas tipo "investigador" pasa el
output por una persona "lint/crítica" antes de mostrarlo al usuario.

**Mapping personas → critic:**
```
einstein     → repo-evaluator (rigor académico)
novalbos     → terry-davis (corrección técnica del código)
warren       → tio-gilito (consistencia financiera)
profesor-fisica → einstein (validación conceptual cruzada)
```

**Trigger:** solo si `risk_level >= medium` y output >300 chars.

**Implementación:** sub-llamada con prompt
*"Audita esta respuesta de <persona origen> contra estas reglas: …
Si todo OK responde 'PASS'. Si hay problemas, lista cada uno con cita."*

**Output:** si critic dice PASS → mostrar respuesta original. Si critique
encuentra issues → preceder con bloque ⚠️ con la crítica concisa.

---

### Phase 4 — Execution Grounding para coding agents (2-3 h)

**Qué:** Para personas terry-davis y novalbos cuando ejecutan/editan código,
hook post-tool que verifica:

1. **Sintáctico:** correr linter (ruff, eslint, etc.) sobre el output
2. **Imports:** verificar que cada `import X` resuelve en el venv/paquete activo
3. **CLI flags:** si la respuesta propone un comando con flags, ejecutar
   `<comando> --help` y verificar que cada flag mencionado existe
4. **Tests:** si añade nueva función, exigir que añada test (TDD ya en SKILL.md
   pero hoy no es enforcement — convertir a check duro)

**Implementación:** nuevo hook `hooks/exec-grounding.py` (PostToolUse,
matcher: `Edit|Write|Bash`) que aborta y avisa si encuentra:
- Función inexistente importada
- Flag CLI inventado (curl --json no existe en curl<7.82)
- Sintaxis inválida (linter exit !=0)

**Output:** bloque ⚠️ si falla, con sugerencia de fix.

---

### Phase 5 — Intent-Based Gate Integration (2-3 h)

**Qué:** Pegamento que une todo lo anterior. El intent-dispatcher decide
qué subset de Phases 1-4 activar según `risk_level`.

**Tabla de decisión:**
```
risk=low     → nada (generación directa, comportamiento actual)
risk=medium  → Phase 1 (entropy probe) + Phase 2 (provenance)
risk=high    → Phases 1+2+3 (entropy + provenance + janus critic)
risk=critical → Phases 1+2+3+4 + auto-/triple (Codex+Gemini cross-verify)
```

**Bypass:** flag `--no-anti-hallucination` para skipear todo (debug/dev).

## Acceptance criteria

- [ ] Risk classifier acierta ≥90% en corpus de 30 pares
- [ ] Semantic Entropy Probe se dispara solo en risk=high (no false positives medible)
- [ ] Provenance enforcement bloquea entries malformadas en vault
- [ ] Janus hook produce critique útil >70% de las veces (juicio USER)
- [ ] Execution grounding caza ≥5 flags/imports inventados en test corpus adversarial
- [ ] Suite tests pasa 100% (no regresiones en routing actual)
- [ ] Latencia añadida en risk=low: ~0 ms (no se activa)
- [ ] Latencia añadida en risk=high: <2× baseline (aceptable trade-off)

## Riesgos

| Risk | Mitigación |
|---|---|
| Entropy probe demasiado caro en uso normal | Solo activar en risk=high; cachear embeddings |
| Janus hook → bucle infinito (critic critica al critic) | Hard cap: una sola pasada por respuesta |
| False positives bloquean trabajo legítimo | Warning soft, no abort. Bypass flag disponible |
| Provenance schema rompe vault legacy | Backward-compat con source_uri="legacy" |
| Risk classifier mal calibrado al inicio | Logs de telemetría para auto-tune; revisar mensual |
