# v15.2 Public Release — Spec

The first public, installable release of ULTRON. Tagged from `main` after the
checklist in `docs/RELEASE-CHECKLIST-v15.2.md` is green. This spec is the
canonical source of truth for what v15.2.0 ships and what it does not. All
disagreements with `REPO-SPLIT-PLAN.md` or the checklist are flagged at the end.

## 1. Problem

ULTRON has lived for ~15 versions as a personal monorepo at `~/.ultron/`. It is
now stable enough that other developers should be able to fork, clone, install
and run it on a clean machine — but the current tree is unshippable:

- Hard-coded `C:\Users\USER` paths in cockpit Python, Tauri commands and hooks.
- Personally named skills (Terry, Mike, Tolkien, Tio Gilito, Warren, etc.) that
  carry the author's identity and references to private files.
- Personal data co-located with code: `MEMORY.md`, `personal/`, `cockpit/news/*.html`,
  `brain_index/index.db`, `qdrant_storage/`, `alerts.jsonl`.
- Single repo conflates installable tool, curated skill packs and the empty
  vault skeleton.

**Audience:** external developers who want to install ULTRON on their own
Windows 11 machine and configure their own Claude Code / Codex / Gemini
subscriptions. Not the author. Not enterprise. Not paying customers.

## 2. Non-Goals

v15.2.0 explicitly does NOT ship:

- Mobile apps (iOS, Android).
- A hosted SaaS version, account system or cloud-synced vault.
- Automatic LLM API-key setup, key vending or key rotation. Subscription CLIs
  only (`claude`, `codex`, `gemini`).
- Telemetry, analytics, crash reporting, anonymous usage stats. Zero outbound
  network traffic except calls the user initiates through the wrapped CLIs.
- Paid features, license tiers, feature flags gated by purchase.
- macOS or Linux full support. Code is largely portable but only Windows 11 is
  tested.
- Auto-updater (deferred — see Section 11).
- Translations / i18n. UI ships ES/EN as it currently is.
- Migration tooling from the v15.1.x personal monorepo. Personal users stay on
  their existing clone; the public repo is a separate genealogy.

## 3. Constraints

- **Subscription-only.** No `*_API_KEY` env vars touched by ULTRON code itself.
  All model access through CLIs the user has already authenticated.
- **Cross-platform aspirational, Windows-first reality.** PowerShell wrappers
  with `.sh` parity is a goal, not a gate. README documents Windows 11 as the
  only tested target for v15.2.0.
- **No invasive permissions.** Tauri capabilities ship with the narrowest
  allowlist that still lets the app function. Destructive operations always
  prompt.
- **Open-source MIT.** `LICENSE` at the root of each of the three target repos,
  copyright 2026 USER SURNAME. No CLA.
- **No personal data ships.** Verified by grep across `HEAD` and history.
- **All paths portable.** `Path.home()` in Python, `dirs::home_dir()` in Rust,
  `$HOME` / `$env:USERPROFILE` in shell. Zero `C:\Users\USER` in tracked
  files.

## 4. Inputs

What already exists and feeds into this release:

- **v15.1.x feature set** (stable, shipped incrementally over the previous
  weeks):
  - 10-tab Tauri 2 + React 19 Control Center.
  - L0/L1/L2 hierarchical memory with FTS5 brain index and optional Qdrant.
  - Plans tab with PLANS.json single source of truth, archive-on-resolve.
  - Skills browser, MCPs dashboard, News (HTML newsletter), Schedules,
    Sessions presets, Stats, Settings JSON editor with Codex assist, Usage
    live.
  - PowerShell dispatcher + Python cockpit (`scripts/cockpit/*.py`).
- **Documentation**: `README.md`, `CONTRIBUTING.md`, `LICENSE` at repo root
  (all three present as of v15.1.1).
- **Installer**: `scripts/install.ps1` (Windows). `install.sh` is a stretch
  goal — see Section 11.
- **Repo split plan**: `docs/REPO-SPLIT-PLAN.md` (three target repos:
  `ultron`, `ultron-skills`, `ultron-memory-template`).
- **Persona-strip pass**: three skills already renamed (`pana →
  personal-assistant`, `alfred → windows-admin`, `don-claudio →
  gamedev-engineer`). Ten more to audit; see
  `docs/personas-release-decision.md`.
- **Skill renaming pass**: aliases-stub approach. Old names remain in the
  user's local `~/.claude/skills/` tree as deprecated stubs that route to the
  new name via a `SKILL_ALIASES` map.
- **Capabilities allowlist** (`docs/ULTRON-GENESIS-CAPABILITIES.md`): 32
  hardcoded regex validators across the deadwood-sentinel, MCP allowlist and
  hook-input validator. They work today but are repeated literals across
  files; a `build.rs` / `cargo xtask` pass to generate them from a single
  manifest is scheduled as v15.2.1 follow-up, not a v15.2.0 blocker.

## 5. MVP — what MUST be in v15.2.0

The minimum bar to publicly tag:

- `LICENSE` (MIT) at the root of each target repo.
- `README.md` rendered correctly on the GitHub preview pane: headings,
  fenced code blocks, ASCII tree diagram, all relative links resolve.
- `CONTRIBUTING.md` at the root of `ultron` with branching, commit and PR
  rules already in place.
- `scripts/install.ps1` dry-run completes on a clean Windows 11 VM with no
  prior `~/.ultron/`. Doctor script reports green at the end.
- **No persona-named skills shipped** in `ultron-skills`. Generic role names
  only (`senior-engineer`, `ui-designer`, etc.). Persona aliases (`terry`,
  `mike`, `tolkien`, ...) stay private. See
  `docs/personas-release-decision.md` for the per-skill decision and the
  conservative ship set.
- `features.json` toggles respected by the Control Center: every tab listed
  in `cockpit/projects.json` corresponds to a feature flag the installer
  can disable.
- Build reproducible on a clean machine: `git clone` → `scripts/install.ps1`
  → `cd control-center && npx tauri build` succeeds.
- No personal data findable via grep across the public repo (`HEAD`) or its
  history (`git filter-repo --analyze` baseline clean).

## 6. Fail-fast order

Sequence of checks to run before tagging `v15.2.0`. The first failure aborts;
do not continue down the list.

1. **Path grep**: `grep -r "C:\\Users\\USER"` against the staging branch
   under `scripts/`, `control-center/src/`, `control-center/src-tauri/`,
   `cockpit/`, `docs/` → must return 0 hits.
2. **Personal-data grep**: search tracked files for `*.jsonl`, `personal/`,
   `cockpit/news/*.html`, `brain_index/index.db`, `qdrant_storage/`,
   `MEMORY.md` → must return 0 hits after `git rm --cached` of any stragglers
   and `.gitignore` updates per `REPO-SPLIT-PLAN.md` § Pre-split checklist.
3. **Rust build**: `cargo check --release` from
   `control-center/src-tauri/` exits 0.
4. **TypeScript**: `npx tsc --noEmit` from `control-center/` exits 0.
5. **Python**: `uv run pytest` from repo root passes, excluding any
   personal-tagged or integration suites (`-m "not personal and not integration"`).
6. **Installer dry-run**: `scripts/install.ps1 -DryRun` on a fresh Windows 11
   VM (or `--dry-run` flag if implemented; otherwise full install on a VM
   that gets discarded).
7. **Beta tester smoke**: one external user, one hour of usage on their own
   Windows 11 box, confirms the installer completes and the app launches with
   all configured tabs.
8. **README render**: open the staging branch on `github.com` and verify the
   README preview pane renders headings, tables and code blocks correctly.
9. **Repo split executable**: the split script (or manual procedure
   documented in `REPO-SPLIT-PLAN.md`) runs on a clone of the staging branch
   and produces the three target repos with their respective LICENSE,
   README and `.gitignore` files. Defer the actual push of `ultron-skills`
   and `ultron-memory-template` to immediately after the `ultron` tag — see
   Section 8 for rollback.

## 7. Success Criteria

Boolean acceptance, all must be true:

- [ ] `npx tauri build --no-bundle` succeeds on a machine where the Windows
      account name is not `USER`.
- [ ] `git clone <new-public-repo> && cd ultron && ./scripts/install.ps1`
      on a clean VM produces a working app.
- [ ] Zero personal data findable via grep across the repo at `HEAD` **or**
      in git history. Verify with `git filter-repo --analyze` and the secret
      scanner from `RELEASE-CHECKLIST-v15.2.md` § Pre-flight.
- [ ] All persona-style aliases (`pana`, `alfred`, `don-claudio`, plus
      whichever others stay local) route correctly via the `SKILL_ALIASES`
      map. Verified by activating each alias name in a Claude Code session
      and confirming the new-named skill loads.
- [ ] CI green. Note: the CI workflow itself is **out of scope for
      v15.2.0** but required for v15.2.1; see `CONTRIBUTING.md` § PR
      requirements for the three checks CI will run.

## 8. Rollback

If v15.2.0 ships and something breaks publicly:

- The tag stays in history; do not delete it. Pulling the tag is more
  destructive than an obviously-broken release.
- Cut a `v15.2.1` hotfix branch from the tag. Fix forward.
- Users on the v15.1.x personal monorepo (i.e. the author and anyone who
  cloned that tree directly) are unaffected — the public repo is a separate
  genealogy at a different URL.
- README in the public repo carries an explicit note: *"If you were running
  v15.1.x from a personal clone, do NOT migrate to the public v15.2.0 yet —
  wait for v15.2.1."* This note can be removed once the public release has
  been stable for two weeks.
- The `ultron-skills` and `ultron-memory-template` repos are tagged after
  `ultron` v15.2.0 lands and the beta smoke test passes. If `ultron` v15.2.0
  fails review post-tag, holding the other two repos unpublished means there
  is nothing to revert externally.

## 10. Verification Questions

Decisions that must be answered before the tag is cut:

- **Repo URL / org.** `CONTRIBUTING.md` currently uses
  `https://github.com/<owner>/ultron.git` as a placeholder. Confirm the
  final URL — under the author's personal GitHub, a new org, or somewhere
  else. Update `CONTRIBUTING.md` line 9 and any installer hints.
- **LICENSE choice.** MIT is chosen and present at the root. Confirm with
  any stakeholders whether Apache-2.0 would be preferred for its explicit
  patent grant. If MIT stays, no change. If Apache-2.0, update LICENSE in
  all three target repos before tagging.
- **Docs site.** GitHub Pages off the `/docs` folder is sufficient for
  v15.2.0. Custom domain is not required. Confirm or defer to v15.2.1.
- **Tag scheme.** Continuing the internal `v15.x` series vs. restarting
  public versioning at `v0.1.0` or `v1.0.0`. Current bias: keep `v15.2.0`
  because the changelog, specs and PLANS.json all reference these numbers
  and starting over hides real maturity. Confirm before pushing.

## 11. Open Questions

Items intentionally deferred to v15.2.1 or later, not blockers for v15.2.0:

- **Auto-updater.** Tauri's built-in updater vs. manual download of release
  artifacts from GitHub Releases. Built-in updater requires a signing key and
  a public update manifest URL; manual download is sufficient for an
  early-adopter audience. Defer.
- **`install.sh` for macOS/Linux.** PowerShell-only installer ships in
  v15.2.0; a `bash` port is straightforward but only useful after macOS/Linux
  smoke testing actually happens. Defer.
- **Theme toggle.** UI is dark-only in v15.1.x; adding light theme is
  cosmetic and uncontroversial. Defer.
- **Beta / staging channel.** Not needed at this scale of audience. Defer.
- **Translations.** UI is bilingual ES/EN inconsistently; consolidating to
  English-default with a `lang/es.json` override is a v15.3 conversation.
- **Telemetry.** Keep none. Re-evaluate only if a clear privacy-respecting
  use case appears.
- **Capabilities allowlist refactor.** The 32 hardcoded regex validators
  documented in `ULTRON-GENESIS-CAPABILITIES.md` work but are duplicated
  across `deadwood-sentinel`, MCP allowlist and hook-input validator. A
  `build.rs` / `cargo xtask` pass that generates them from a single manifest
  is scheduled for v15.2.1. Not a v15.2.0 blocker — the validators are
  correct, just not DRY.
- **CI.** GitHub Actions workflow running the three CONTRIBUTING.md checks
  (`cargo check --release`, `npx tsc --noEmit`, `uv run pytest`) is
  required for v15.2.1 but explicitly out of scope for the first tag.

## Disagreements with adjacent docs

Flagged here so reviewers do not silently override:

- `docs/REPO-SPLIT-PLAN.md` lists `Tio-Gilito, Tolkien, Einstein, Terry,
  Mike, Warren, Jordan, Novalbos, Kirkardo, Tyson` as personas to rename to
  generic role aliases and publish in `ultron-skills`. This spec, together
  with `docs/personas-release-decision.md`, recommends a more conservative
  ship set: only technical/generic skills go to `ultron-skills` in v15.2.0;
  the persona-flavored ones either stay local or move to a future
  `ultron-skills-personas` repo. Resolve before tagging the
  `ultron-skills` repo. The `ultron` repo itself is unaffected.
- `docs/RELEASE-CHECKLIST-v15.2.md` § Release artifacts contains an item
  about the auto-updater. This spec defers the auto-updater to v15.2.1
  (Section 11). The checklist item should be marked "deferred" rather than
  blocking the tag, or removed.
- `CONTRIBUTING.md` § Out of scope rules out Docker. `REPO-SPLIT-PLAN.md`
  does not mention Docker. No actual conflict, but worth confirming both
  documents agree before publishing them as the public contract.
