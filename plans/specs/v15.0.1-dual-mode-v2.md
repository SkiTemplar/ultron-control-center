# v15.0.1 — Dual Mode v2: codex-plugin-cc + Gemini CLI vía suscripción

## Contexto

El sistema multi-modelo peer actual de ULTRON es casero: `shared-duet.ps1` / `codex-duet.ps1` lanzan Codex CLI (`--sandbox read-only --ignore-user-config`) y el output vuelve como resultado de Bash → contamina el contexto principal. Gemini va por MCP con `GEMINI_API_KEY` (modelo Flash, no Pro; depende de API key).

En marzo 2026 OpenAI publicó **`openai/codex-plugin-cc`** — plugin oficial para Claude Code: comandos `/codex:review`, `/codex:adversarial-review`, `/codex:rescue` + `/codex:status` `/codex:result` `/codex:cancel`, subagente `codex:codex-rescue`, **auth vía suscripción ChatGPT** (no API key obligatoria), config en `~/.codex/config.toml` (`model`, `model_reasoning_effort`). Background jobs + subagente = la salida de Codex queda fuera del contexto principal. Es lo que queríamos.

Decisión USER 2026-05-12: adoptar el plugin, migrar el plumbing casero, y para Gemini quitar la API key y usar el CLI con output a archivo `.md` legible.

## Workstreams

### WS1 — Adoptar `codex-plugin-cc`
- Instalar (lo ejecuta USER, son slash-commands):
  ```
  /plugin marketplace add openai/codex-plugin-cc
  /plugin install codex@openai-codex
  /reload-plugins
  /codex:setup
  ```
- Verificar auth: `!codex login` si no está logueado (suscripción ChatGPT, NO API key).
- `~/.codex/config.toml`: pin `model` + `model_reasoning_effort` (no dejar que un `.codex/config.toml` de proyecto los cambie sin querer — load order: user → project-if-trusted).
- **Review-gate DESACTIVADO** (puede crear bucle Claude↔Codex infinito). Si se usa, acotado a los límites de rounds ULTRON.
- Mapear sub-modos ULTRON sobre el plugin:
  - `/minidual` (1 round) → `/codex:review`
  - `/dual` (3 rounds) → `/codex:adversarial-review` con iteración acotada
  - `/maxdual` (5 rounds, sólo ULTRA) → `/codex:adversarial-review` + `/codex:rescue` para sub-tareas pesadas (con confirmación)
- Mantener la capa conceptual ULTRON: **LOW prohíbe Dual completamente** · Codex read-only salvo `/codex:rescue` (requiere confirmación explícita) · si Codex sugiere → Claude escribe · ChatGPT subscription = sólo modelos permitidos por el plan.

### WS2 — Gemini vía suscripción (sin API key)
- Usar el CLI `gemini` (ya instalado, `~/AppData/Roaming/npm/node_modules/@google/gemini-cli`) con login OAuth (cuenta Google / Gemini Code Assist) — **NO** `GEMINI_API_KEY`.
- Patrón de invocación (wrapper `~/.ultron/scripts/gemini-peer.ps1`):
  ```
  gemini -m <modelo-Pro> -p "<prompt>. IMPORTANTE: escribe tu respuesta completa en Markdown en el archivo <ruta>.md y nada más por stdout."
  → Claude hace Read de <ruta>.md
  ```
  Output a archivo `~/.ultron/.tmp/gemini-out/<timestamp>.md` → se lee con `Read`, no contamina con stdout largo.
- Verificar que el CLI permite forzar el modelo **Pro** bajo suscripción y no degrada a Flash. Si la suscripción no da Pro por CLI → documentar el límite y decidir (mantener Flash vía CLI sin API key, o aceptar API key sólo para Pro).
- **Quitar `GEMINI_API_KEY`** de `~/.claude/settings.json` > mcpServers > gemini (y el server MCP de Gemini si ya no se usa). El flujo `second-opinion` / Gemini delegation pasa a ser CLI-only.
