# ULTRON v13.0 "The Truth Boundary" — Architecture Blueprint

## Premisa

El audit Kirkardo TOTAL Triple del 2026-05-03 identificó como **gran miss arquitectónico**:

> "El sistema no tiene 'truth ownership boundary'. Config, docs, manifests, vault, jobs, proposals, y audits compiten autoridad sin árbitro declarado. Por eso stale docs, empty allowlists, dead proposals y LEGACY code coexisten sin failure."
>
> — Codex Round 3 (gpt-5.5)

v13.0 establece autoridad declarada y trazabilidad para cada artefacto del sistema, eliminando la posibilidad de drift silencioso.

## Objetivos primarios

1. **Truth Ownership Manifest** (`SOURCE-OF-TRUTH.md`) — declara autoridad cuando hay drift
2. **AutoUpdater decision binaria** (F06) — LEGACY explícito o resucitar
3. **CC-memory indexada en brain_index** (F07) — eliminar drift silencioso bridge
4. **Constitution = 14 personas con safety_gates** (F08 ya completado en v12.6)
5. **Audits → brain_index FTS5** — audits son fuente, no terminales
6. **Kirkardo Rubric Artifact** (`kirkardo-rubric.json`) — rúbrica versionada
7. **Memory bridge bidireccional** con conflict detection
8. **ARCH-01 path migration** — top 10 scripts adoptan `ultron_paths`

## 1. SOURCE-OF-TRUTH.md (nueva)

**Path:** `~/.ultron/cockpit/SOURCE-OF-TRUTH.md`

**Schema:**

```markdown
# SOURCE OF TRUTH — ULTRON v13.0

When two artifacts disagree, this document declares which wins.

## Personas
- canonical: `~/.claude/skills/<persona>/SKILL.md`
- derived: `skill_manifest.json` (regenerated by registry_sync)
- derived: `skills-registry.json` (regenerated)
- derived: `agent_manifest.json` (Phase-0b agents only)
- governance: `~/.ultron/skill_cache/constitution.json` (manual, validated by personas_ssot.py --check)

## Versions
- canonical: `~/.ultron/INDEX.md` `<version>` field
- derived: docstrings in CLAUDE.md ULTRON header
- derived: SKILL.md ULTRON header
- consistency check: `consistency_check.py` (Stop hook)

## Project list
- canonical: `~/.ultron/cockpit/projects.json`
- generator: `scan_projects.py` (rebuilds nightly)
- docs: count must NOT be hardcoded; reference projects.json directly

## Memory layers
- L1 canonical: `~/.ultron/brain_index/index.db` (FTS5)
- L1 source: `~/.ultron/INDEX.md` + `~/.ultron-vault/*.md` + `~/.claude/projects/*/memory/*.md`
- L2 canonical: `~/.ultron-vault/`
- L3 canonical: `github.com/SkiTemplar/ultron-memory` (auto-push)
- bridge: `memory_bridge.py` (CC↔vault, bidirectional in v13.0)

## Self-improve pipeline
- canonical: `~/.ultron/cockpit/pending_actions.json`
- audit ingest: `audit_to_pending.py` (Sprint 4)
- L2 proposals: LEGACY (auto_updater.py:315/537), do NOT use
- L1 audit: `auto_updater.py audit/scan` (active)

## Rubric
- canonical: `~/.ultron/cockpit/kirkardo-rubric.json` (versioned)
- consumer: `repo-evaluator/SKILL.md` references `rubric_version: X.Y`

## Drift detection
- automated: `consistency_check.py` runs on Stop, reports drift
- manual: `kirkardo_regression.py audit-A audit-B`

## Conflict resolution
1. canonical source wins by default
2. if canonical is missing/corrupt, fall back to most-recent derived + log alert
3. if derived contradicts canonical, log to `~/.ultron/cockpit/drift-alerts.jsonl` + surface in ALERTS.md
```

**Why:** sin este documento, cada Kirkardo re-descubre los mismos drifts. Establecer autoridad explícita lo hace medible.

**How to validate:** crear test `test_source_of_truth.py` que valida que cada documento referenciado (skill_manifest, INDEX.md, projects.json...) existe y es legible.

## 2. F06 — AutoUpdater Decision Binaria

**Problema actual:** `auto_updater.py:315 cmd_propose=LEGACY`, `:537 cmd_full=LEGACY`. Pero `cmd_apply:471` NO está marcado (Codex catch). `SKILL.md` ULTRON declara "L1→L2→L3 ✅" — drift documentado.

**Decisión propuesta:** LEGACY explícito.

**Plan:**

1. Renombrar funciones legacy con prefijo `_legacy_` y emitir DeprecationWarning si llamadas:
   ```python
   def cmd_propose(args):
       """LEGACY (v12.4+). Use audit_to_pending.py instead."""
       import warnings
       warnings.warn("cmd_propose is LEGACY since v12.4. Use audit_to_pending.py.", DeprecationWarning)
       sys.exit(2)
   ```

2. Eliminar las entradas legacy del argparse en `auto_updater.py:662` o reemplazar con error message.

3. Actualizar `~/.claude/skills/ultron/SKILL.md` y `CLAUDE.md` para reflejar que el pipeline activo es:
   ```
   auto_updater.py audit/scan → audit_to_pending.py → pending_actions.json → manual review
   ```

4. Mantener `proposals/` directorio por compatibilidad (no romper estructura de los 2 archivos `.applied.json`).

**Aceptación:**
- [ ] `grep -l "L1.*L2.*L3" ~/.claude/skills/ultron/` retorna 0 archivos con claim activo
- [ ] `cmd_propose --help` o `cmd_apply --help` retornan error exit code 2 con mensaje LEGACY
- [ ] consistency_check.py incluye un assertion sobre claims de pipeline

## 5. F13 — Job exit_code Integrity Invariant

**Problema actual:** Job `4c95dc76540b` ejecutó `print(hello)` (NameError) pero status=`done` con exit_code=`null`.

**Plan:**

1. En supervisor de jobs (script en `cockpit/`):
   ```python
   process.wait()
   meta["exit_code"] = process.returncode
   meta["status"] = "done" if process.returncode == 0 else "failed"
   meta["completed_at"] = datetime.now().isoformat()
   ```

2. Invariant CHECK al inicio de cada `ultron jobs status`:
   ```python
   bad = [p for p in JOBS_DIR.glob("*/meta.json")
          if json.load(p).get("status") in ("done","failed") and json.load(p).get("exit_code") is None]
   if bad:
       print(f"⚠️  {len(bad)} jobs with status=done/failed but exit_code=null", file=sys.stderr)
   ```

3. Backfill script: `ultron jobs repair` — para jobs viejos con null, set exit_code=-1 y status=corrupted.

**Aceptación:**
- [ ] cero jobs con `status in ("done","failed") and exit_code is None`
- [ ] `print(hello)` reproducción correctamente registra status=failed

## 9. Memory Bridge Bidireccional con Conflict Detection

**Problema actual:** `memory_bridge.cmd_ingest` solo CC→vault. Si usuario edita vault directamente, drift silencioso vs CC source.

**Plan:**

1. Nueva flag: `memory_bridge.py sync --bidirectional`.
2. Para cada par (source, mirror): comparar SHA. Si diff:
   - Si source mtime > mirror: re-ingest CC→vault
   - Si mirror mtime > source: log conflict, NO sobrescribir source automáticamente (user edita vault como decisión consciente normalmente)
3. `bridge-index.json` tracks `needs_review: true` para conflicts.
4. Comando `ultron memory diff <file>` muestra diff lado-a-lado.

**Aceptación:**
- [ ] caso real de esta sesión (MEMORY.md SHA divergente) detectado en `bridge-index.json`
- [ ] `ultron memory diff MEMORY.md` muestra diff
