An AI that remembers you.v14.x.x

ULTRON is a personal AI operating system built on top of Claude Code. It runs in your terminal, never forgets what you told it last week, routes your prompts to the right specialist before Claude even starts thinking, and checks itself every session so it doesn’t drift on you.

Not a plugin. Not a prompt template. An operating layer. One person built it, for himself, because nothing else did what he needed.

1157 tests passing 780 notes indexed 0.58 ms dispatch 1380 / 1500 tok overhead

01 — The problem with AI assistants

Every AI session starts from zero. You explain the project again. You paste the context again. You re-type the architecture you described three days ago. The AI is smart — it just doesn’t know who you are.

That’s not an assistant. That’s a colleague with amnesia who happens to be very good at their job when they remember things.

The other problem is routing. “Hey, help me with my code” could mean 100 different things. The right specialist for a UE5 shader bug is not the same one you want for a financial analysis or a security audit. A vanilla Claude setup doesn’t know the difference until you tell it.

ULTRON solves both. Memory that actually persists. Routing that fires before the first token is spent. A system that knows which tool to reach for — automatically.

04 — Architecture

Six layers. Each one has one job.

You don’t need to understand all six to use ULTRON. But knowing the shape helps when something breaks or when you want to extend it. The key rule: each layer only loads what the layer above it requests.

  1. LAYER 0 Claude Code Session Opus 4.7 orchestrator · ~200K context window · the brain
  2. LAYER 1 Hooks Fire on session events · route intent · sync memory · block injections
  3. LAYER 2 ZTMSI — Zero-Token Memory & Skills Index SQLite FTS5 · 780 notes · answers in <5 ms · costs zero tokens
  4. LAYER 3 Stratified Memory L0 hot (400 tok) · L1 indexed · L2 cold vault · L3 remote git backup
  5. LAYER 4 Skills & Manifest 392 entries · SSOT frontmatter · security-scanned at admit time · auto-discovered
  6. LAYER 5 Multi-Model Codex CLI peer critic · Gemini long-context · sandboxed · file-based async
  7. LAYER 6 Observability Append-only alerts bus · dispatcher telemetry · doctor self-check · TUI dashboard

05 — Capabilities

Fourteen subsystems. All verified at release.

Every item below has a script path, a test, or a documented protocol. Nothing is aspirational.

Power Modes

Five session intensities. LOW locks the budget. ULTRA opens the full pipeline including Dual Mode and vault sync. LEARN captures and stores what the session teaches.

LOW · MEDIUM · HIGH · ULTRA · LEARN

Layered Memory

L0 primes every session in under 400 tokens. L1 is indexed and queryable. L2 is the cold vault with git history. L3 is the remote backup. Each layer is independent; any can be rebuilt.

L0 + L1 + L2 + L3

Brain Index (ZTMSI)

FTS5 SQLite over every vault note, chunked to paragraph level. BM25 ranking. Zero tokens consumed — it answers before the LLM is involved.

780 notes · ~10,240 chunks · <5 ms median

Intent Dispatcher

56 pre-compiled regex rules. Classifies your prompt in 0.58 ms. Routes to the right skill, loads the right context, suggests the right mode — before Claude reads a single character.

p95 0.58 ms · 40 ms budget · 52× margin

Hooks Pipeline

Nine hooks on Claude Code session events. Validated stdin, 4 MiB payload cap, depth limit 10. Never blocks the user. Auto-approves read-only tools. Blocks dangerous Bash patterns.

SessionStart · UserPromptSubmit · PreToolUse · PostToolUse · Stop

Skills Manifest

Single source of truth for 392 skills. 22 curated personas + 370 auto-discovered. Schema-validated on every sync. Kirkardo can audit any skill from the TUI.

392 entries · SSOT frontmatter · JSON Schema validated

Independent skill reviewer. Runs on Sonnet (quick) or Opus (full). Reads active ALERTS before auditing — flags CVEs or API changes that affect the skill under review. Score out of 10.

06 — Specs

Numbers. Not adjectives.

Click any row for context.

Memory

Notes indexed780

Markdown notes in the L2 vault plus the L1 bridges (projects, sessions, skills). Each carries a frontmatter token estimate and a layer tag used by the brain index for BM25 scoring.

Chunks queryable~10,240

Paragraph-level chunks produced by the frontmatter backfill. The FTS5 chunks_fts table is what the dispatcher queries. Each chunk is ~135 tokens on average.

L0 hot-context budget≤ 400 tok

Pre-computed by SessionStart into ~/.ultron/.tmp/context.md. Includes last sessions, top stale notes, and any unacked alerts at warn or above.

Vault layersL0 + L1 + L2 + L3

L0 is the 400-token hot primer. L1 is the FTS5 index. L2 is the cold git vault at ~/.ultron-vault/. L3 is the remote backup. Any layer can be rebuilt from the ones below it.

Routing

Dispatcher rules56

Pre-compiled regex patterns covering architecture, code review, debugging, UE5, finance, security, standup, news, audit (Kirkardo), and more. First match wins; confidence threshold 0.70.

Dispatcher internal p950.58 ms

Measured inside intent-dispatcher.py, excluding Python startup. The 40 ms hook budget gives a 52× margin. No tokens consumed on a cache hit.

Slash short-circuit p950.001 ms

Slash commands skip the brain-index path entirely. ZTMSI cost is zero. Routing line emitted immediately.

FTS5 median query~4 ms

Live measurement on the 10,047-chunk index. p50 3.9 ms. Falls back to ZTMSI when dispatcher rules miss and confidence ≥ 0.70.

Security

Prompt-injection rules12

PI001–PI012. PI012 detects embedded system prompt overrides. Block beats quarantine beats warn. Trusted-source flag can downgrade warn to allow — never block.

Probed in parallel at SessionStart with a 3-second per-probe timeout. Pending probes at deadline are marked degraded. The session continues regardless.

09 — How we got here

Six sprints from broken to Genesis.

ULTRON was rebuilt from scratch because the old version was accumulating layers like geological sediment. Every feature added more tokens, more files, more confusion. Genesis was a deliberate reset with a clear architecture and release gates.

  1. S0 Clean House — Delete the sediment v13.5
  2. S1 Silent Exec + Alerts bus — No popups, append-only events v13.6
  3. S2 ZTMSI + Dispatcher — Zero-token memory, 0.58 ms routing v13.7
  4. S3 Layered Memory — L0/L1/L2/L3 with context packet builder v13.7
  5. S4 Manifest — 392-entry SSOT, auto-discover, security pre-flight v13.7.0
  6. S5 Genesis — All gates green, TUI polished, ALERTS wired end-to-end v14.0.0
